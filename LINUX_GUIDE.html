1. GUI Library Information

✅ Using GTK 3
This project uses GTK 3 - a modern, cross-platform GUI toolkit.

Why GTK 3?

  • Modern & Feature-rich - Much better than raw X11/Xlib
  • Native Look - Integrates with Linux desktop themes
  • Easy to Use - Proper widgets (buttons, text views, entries)
  • Well-maintained - Active development and documentation
  • Thread-safe - Using gdk_threads_add_idle() for UI updates

3. Finding Shared Folder Path in VMware

Since you have shared folders enabled in VMware, follow these steps:

Method 1: Check /mnt/hgfs (Most Common)

ls /mnt/hgfs

If you see your shared folder name, the path will be:

/mnt/hgfs/YOUR_SHARED_FOLDER_NAME/

Method 2: If /mnt/hgfs is Empty

You may need to mount the shared folders manually:

# Create mount point if it doesn't exist
sudo mkdir -p /mnt/hgfs

# Mount VMware shared folders
sudo vmhgfs-fuse .host:/ /mnt/hgfs -o allow_other

# Now check again
ls /mnt/hgfs

Method 3: If Still Not Working

Install or reinstall VMware tools:

# Install open-vm-tools
sudo apt-get install -y open-vm-tools open-vm-tools-desktop

# Reboot the VM
sudo reboot
📁 Your Project Path
Based on your folder name, your path will likely be: 
/mnt/hgfs/Os project (linux )/

5. Running the Applications

Option A: Socket Chat (Client-Server over Network)

This uses TCP/IP Sockets and Multithreading. Can work over a network!

Terminal 1 (Server) Terminal 2 (Client) 
cd "/mnt/hgfs/Os project (linux )/"
./server
 
cd "/mnt/hgfs/Os project (linux )/"
./client

Using the Client:

  1. Keep IP as 127.0.0.1 (localhost) for same machine
  2. Click the CONNECT button
  3. Wait for "Connected" status
  4. Type your message in the input box
  5. Press Enter or click SEND

Option B: Shared Memory Chat (Same Machine)

This uses POSIX Shared Memory and Semaphores. Only works on the same machine!

Terminal 1 Terminal 2 
cd "/mnt/hgfs/Os project (linux )/"
./shm_chat
 
cd "/mnt/hgfs/Os project (linux )/"
./shm_chat

Both windows will get unique User IDs and can chat with each other through shared memory!

5B. Running Client on a Different Device (Network Chat)

🌐 Network Setup
This section explains how to run the server on one VMware VM and the client on a different VMware VM (or device), both connected to the same WiFi/hotspot.

Prerequisites

  • Both devices/VMs connected to the same network (WiFi hotspot, router, etc.)
  • VMware network set to Bridged Mode
  • Code compiled on both machines

Step 1: Configure VMware Network (BOTH VMs)

1
Open VMware Settings
  1. In VMware, go to VM → Settings (or right-click VM → Settings)
  2. Select Network Adapter
  3. Change from "NAT" to "Bridged: Connected directly to the physical network"
  4. Check "Replicate physical network connection state"
  5. Click OK
⚠️ Why Bridged Mode?
  • NAT mode = VMs get private IPs, can't see each other
  • Bridged mode = VMs get IPs on real network, can communicate

Step 2: Find Server's IP Address

2
Get IP on Server Machine

On the VM that will run the server, open terminal and run:

ip addr show

Or the simpler command:

hostname -I

Look for an IP like 192.168.x.x or 10.x.x.x

📝 Example Output
$ hostname -I
192.168.1.105

In this example, the server IP is 192.168.1.105

Step 3: Start Server

3
Run Server on First VM
cd "/mnt/hgfs/Os project (linux )/"
./server

The server will show: "Waiting for client on port 8080..."

Step 4: Connect Client from Second Device

4
Run Client on Second VM
cd "/mnt/hgfs/Os project (linux )/"
./client

In the client window:

  1. Replace 127.0.0.1 with the server's IP address (e.g., 192.168.1.105)
  2. Click CONNECT
  3. Wait for "Connected" status
  4. Start chatting!

Troubleshooting Network Connection

❌ "Connection failed" or "Connection refused"

Try these fixes:

  1. Check firewall - Disable or allow port 8080: 
    sudo ufw allow 8080/tcp
  2. Ping test - Make sure VMs can see each other: 
    ping 192.168.1.105
  3. Check server is running - Make sure server started first
  4. Verify correct IP - Double-check the IP address
❌ VMs can't ping each other
  1. Confirm both VMs are in Bridged Mode
  2. Restart network in VMs: 
    sudo systemctl restart NetworkManager
  3. Make sure both connected to same WiFi/network
❌ IP shows 127.0.0.1 only

The VM isn't getting a real network IP. Check:

  1. VMware network is set to Bridged, not NAT
  2. Host machine is connected to WiFi/network
  3. Restart the VM after changing network settings

6. Making Executables Permanent (No ./ Required)

To run executables from anywhere without typing ./ every time:

Option A: Copy to System Directory (Recommended)

sudo cp "/mnt/hgfs/Os project (linux )/server" /usr/local/bin/chat-server
sudo cp "/mnt/hgfs/Os project (linux )/client" /usr/local/bin/chat-client
sudo cp "/mnt/hgfs/Os project (linux )/shm_chat" /usr/local/bin/shm-chat

Now you can run from anywhere:

chat-server
chat-client
shm-chat

Option B: Create Symbolic Links

sudo ln -s "/mnt/hgfs/Os project (linux )/server" /usr/local/bin/chat-server
sudo ln -s "/mnt/hgfs/Os project (linux )/client" /usr/local/bin/chat-client
sudo ln -s "/mnt/hgfs/Os project (linux )/shm_chat" /usr/local/bin/shm-chat

Option C: Add to PATH (Temporary - Session Only)

export PATH=$PATH:"/mnt/hgfs/Os project (linux )/"

7. Troubleshooting

❌ "Cannot open display"

Make sure you're running in a graphical environment, not SSH.

echo $DISPLAY
# Should show :0 or similar
❌ "GTK not found" or "pkg-config" errors
sudo apt-get install -y libgtk-3-dev pkg-config
❌ "Permission denied"
chmod +x build.sh server client shm_chat
❌ Shared folders not visible
sudo vmhgfs-fuse .host:/ /mnt/hgfs -o allow_other
❌ "Address already in use" (Server)

The port 8080 is already being used. Either:

  • Wait a minute and try again
  • Kill the old process: sudo killall server
